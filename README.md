# Smart Vision-Based Driver Safety Monitoring System

An adaptive, multi-cue driver drowsiness detection system that runs
entirely on a laptop's built-in webcam — no Raspberry Pi, infrared
camera, external sensors, EEG, steering sensors, or mobile app required.

It combines a MediaPipe Face Mesh facial-landmark front end, a custom CNN
with a Convolutional Block Attention Module (CBAM) back end, temporal
smoothing via a sliding window, and a two-gate confidence check before any
alert is raised — implemented per `Implementation_Strategy_Driver_Safety_
System.docx`.

---

## 1. Pipeline

```
Laptop Webcam
   -> Continuous Frame Capture
   -> Face Detection (MediaPipe Face Mesh)
   -> 468 Facial Landmark Detection
   -> Frame Quality Check          (face? lighting? orientation? landmarks?)
   -> Adaptive Cue Selection       (eyes / mouth / head pose, whichever are reliable)
   -> CNN + CBAM                   (custom CNN, attention on relevant regions)
   -> Sliding Window Analysis      (30-frame majority vote)
   -> Confidence Calculation       (CNN probability agreement with cue evidence)
   -> Threshold Check              (probability AND confidence gates)
   -> Audio Alert
   -> Continue Monitoring
```

If frame quality fails at any point, the system displays **"Insufficient
Data"** and keeps reading frames — it never forces a prediction on an
unreliable frame.

## 2. Folder structure

```
driver_safety_system/
    dataset/        Your training images go here (see dataset/README.md)
    models/         CNN + CBAM model architecture (cnn_cbam.py)
    training/       Data loading, augmentation, callbacks
    testing/        Confusion matrix / ROC / classification report generation
    gui/            Tkinter GUI application
    utils/          Landmarks, quality gate, cue selection, sliding window,
                     alarm manager, logging, image utilities, the pipeline
                     orchestrator that ties every stage together
    cbam/           CBAM (channel + spatial attention) implemented from scratch
    logs/           app.log, prediction_log.csv, training plots, TensorBoard
    screenshots/    Auto-saved screenshots taken at the moment of each alert
    weights/        drowsiness_cnn_cbam.h5 (generated by training) --
                     MediaPipe's landmark model ships inside the pip
                     package, so nothing needs to be manually downloaded
    alarm/          alarm.wav (already generated) + generator script
    README.md
    requirements.txt
    main.py         GUI entry point
    train.py        Train the model on your dataset
    predict.py      Console/OpenCV-window real-time mode
    camera.py       Threaded webcam wrapper
    config.py       Every path/threshold/hyperparameter in one place
```

## 3. Installation (Windows, VS Code)

**Python version:** developed and verified against **Python 3.11** (also
works on 3.9, 3.10, 3.12 — every pinned package in `requirements.txt` has
an official Windows wheel for all four). Check your version with
`python --version` before starting.

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

MediaPipe installs with a plain `pip install mediapipe` on Windows — no
C++ build toolchain required (unlike dlib, which this project used to
depend on).

---

## 4. Manual downloads required: none

Landmark detection uses MediaPipe Face Mesh, whose model ships bundled
inside the `mediapipe` pip package. Once `pip install -r requirements.txt`
finishes, face/landmark detection works immediately — no separate model
file to fetch or place anywhere.

`alarm/alarm.wav` is also already included (a synthesized two-tone alarm)
— nothing to do there unless you want to swap in your own sound.

## 5. Adding your dataset manually

Full instructions with auto-detected folder-name synonyms are in
`dataset/README.md`. Short version:

```
dataset/
    drowsy/        put your "drowsy" images here
    not_drowsy/     put your "alert / not drowsy" images here
```

`train.py` auto-detects class names (case-insensitive, several synonyms
recognised), auto-splits 80/10/10, and adapts to a dataset that already
ships pre-split into train/test folders — you should not need to rename
anything unless your class names are very unusual (see
`dataset/README.md` §3 for the one-line fix if so).

## 6. How to train

```bash
python train.py
```

This will:
- Load and auto-split your dataset (80% train / 10% val / 10% test).
- Apply data augmentation + normalization (training split only).
- Build the custom CNN + CBAM model (no transfer learning).
- Train with EarlyStopping, ModelCheckpoint, ReduceLROnPlateau, and
  TensorBoard logging (`logs/tensorboard/` — view with
  `tensorboard --logdir logs/tensorboard`).
- Save the final model to `weights/drowsiness_cnn_cbam.h5` and the best
  checkpoint to `weights/best_checkpoint.h5`.
- Save training curves (`logs/accuracy_graph.png`, `logs/loss_graph.png`),
  confusion matrix (`logs/confusion_matrix.png`), ROC curve
  (`logs/roc_curve.png`), and a classification report
  (`logs/classification_report.txt`, `logs/test_metrics.json`).

Optional flags: `python train.py --epochs 40 --batch-size 16 --learning-rate 0.0005`

## 7. How to test (re-evaluate without retraining)

```bash
python -m testing.run_tests
```

Reloads the saved model and regenerates the confusion matrix / ROC curve
/ classification report against a fresh test split — useful after
swapping in a different dataset.

## 8. How to run the webcam (GUI)

```bash
python main.py
```

Launches the full GUI: live video with bounding box / landmarks / eye &
mouth region overlays, plus live status, confidence, FPS, active cue,
frame quality, and alert panels. Click **Start Monitoring** to begin.

## 9. How to run the webcam (lightweight console mode)

```bash
python predict.py
```

Same pipeline, shown in a plain OpenCV window instead of the full GUI.
Press `q` to quit. Useful flags: `--headless` (no window, CSV logging
only), `--camera-index 1` (external webcam), `--no-alarm`.

## 10. How to change the dataset / retrain later

Replace or add images under `dataset/drowsy/` and `dataset/not_drowsy/`
(or your equivalently-named folders), then simply re-run:

```bash
python train.py
```

It overwrites `weights/drowsiness_cnn_cbam.h5` with the newly trained
model — no other files need to change. `config.py` centralises every
threshold and path, so if you rename folders or move things around, you
only need to edit that one file.

## 11. Output classes

Binary classification: **Drowsy** vs **Not Drowsy**.

## 12. Key design points (from the implementation strategy)

- **In-app performance metrics** — the GUI (`main.py`) shows the trained
  model's test accuracy and ROC AUC directly in the sidebar, plus a
  "View Full Report" button that opens the full classification report and
  the confusion matrix / ROC curve / training curve images, all without
  leaving the app.
- **Frame quality gate** — never predicts on a bad frame; shows
  "Insufficient Data" instead.
- **Adaptive cue selection** — if eyes are occluded (e.g. sunglasses),
  weight shifts automatically to mouth movement, yawning, and head pose.
- **CBAM** — implemented from scratch (`cbam/cbam.py`), channel attention
  followed by spatial attention, no third-party CBAM package.
- **Sliding window (30 frames)** — majority voting filters out a single
  blink or brief yawn from causing a false alarm.
- **Two-gate confidence check** — an alert only fires when *both* the
  predicted probability *and* a confidence score (agreement between the
  CNN's visual prediction and the rule-based cue evidence) clear their
  thresholds.
- **Never crashes** — camera failures, missing dataset/model/weights,
  corrupted images, no/multiple faces, and permission errors are all
  caught and reported with an actionable message instead of a stack
  trace (see `utils/exceptions.py`).

## 13. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `ModelNotFoundError` on startup | Run `python train.py` first. |
| `CameraError: Could not open webcam` | Close other apps using the camera (Zoom, Teams); check Windows camera privacy settings; try `--camera-index 1` if you have more than one camera. |
| `DatasetError` during training | Check `dataset/README.md` — folder names must resolve to Drowsy / Not Drowsy. |
| `pip install mediapipe` fails / import errors | Make sure you're on the pinned version in `requirements.txt` (`mediapipe==0.10.14`) — newer releases changed their API and require a separate model download. Also check the `protobuf` version matches what's pinned; a mismatched protobuf between `tensorflow` and `mediapipe` is the most common cause of import errors. |
| Alarm doesn't play | Confirm `alarm/alarm.wav` exists (it ships pre-generated); check system audio output device; `pygame.mixer` failures are logged to `logs/app.log` without crashing the app. |
